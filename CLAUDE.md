# CLAUDE.md

## Project

VitaSurf (working name) is a PS Vita port of the NetSurf web browser. It uses NetSurf's framebuffer frontend with a Vita-specific libnsfb surface. JavaScript starts with NetSurf's existing Duktape engine; replacing it with QuickJS is a later phase.

Goal: usable browsing of as many websites as possible, including script-heavy sites and web apps, at 960x544 with buttons and touch, with every page loaded and usable in under 20 seconds on real hardware. A site that does not work, or takes longer, is a bug to fix by making the browser faster or more correct, never by tailoring it to that site.

Non-goals: DRM/EME. Do not add, stub, or work around DRM. WebGL is not a non-goal: it is phase 8.

License: NetSurf is GPLv2, so this project is GPLv2. Every added library must be GPLv2-compatible (QuickJS is MIT, which is fine).

## Platform constraints

- CPU: 32-bit ARMv7 (Cortex-A9, NEON). Toolchain prefix `arm-vita-eabi-`. The compiler defines `__vita__`. An app runs at 333 MHz unless it asks for more: `set_clocks` in `vita_platform.c` raises the ARM clock to 444 MHz and the bus to 222 at startup, after a resume and whenever a page load finds them lower, and every page load logs them ("cpu:").
- Memory is the main constraint. The system has 512 MB total and the app gets only part of it. Set `_newlib_heap_size_user` explicitly, log free memory at startup and after each page load, and treat any unbounded cache as a bug. The newlib heap is sized at startup from the memory then free, less a reserve (`vita/platform/vita_heap.c`), so `_newlib_heap_size_user` is only its fallback. Extended memory mode (`ATTRIBUTE2=12` in the SFO) is verified on hardware and is on in every build (`VITASURF_EXTENDED_MEMORY`, default ON).
- No JIT. Both Duktape and QuickJS are interpreters, so JS performance comes from doing less work, not from engine tricks.
- Screen: 960x544. Front touch reports coordinates at 1920x1088, so divide by 2.
- `app0:` is read-only. All writable data goes under `ux0:data/VitaSurf/`.
- newlib's stdio never asks the system for more than the FILE's buffer holds, a kilobyte unless it is given one, and each request to the memory card costs about a quarter of a millisecond. A file of any size is opened with `vita_fopen_buffered` (`vita_platform.c`, a 128 KB buffer) or given its own with `setvbuf` before the first call, as the script cache does (`BC_IO_BUF`): Wikipedia's 1 MB localStorage took 292 ms to read and 288 ms to write a kilobyte at a time.

## Build

- Requires VITASDK with `$VITASDK` set. Install dependencies with vdpm: curl, openssl, zlib, libpng, libjpeg-turbo, freetype, and SDL2 if the surface uses it. Check exact package names in vdpm before scripting them.
- vdpm's FreeType has no brotli, so it refuses every WOFF2 font, and WOFF2 is what the web serves. `scripts/build-freetype-woff2.sh` builds brotli and then FreeType against it, over the top of vdpm's copies. Without it, an icon font renders as the ligature's name: openmediavault and Audiobookshelf both show that.
- QuickJS is built from `deps/libquickjs` (quickjs-ng v0.14.0, the version vdpm ships) by `scripts/build-quickjs.sh`, not taken from vdpm. Stock quickjs-ng keeps a copy of every function's source, nested functions included, which is 35-47% of the memory compiling a large bundle takes; patch 0243 makes a script's functions share one copy. The startup log says which build is in use ("functions share their script's source").
- A page's scripts and modules are compiled with `JS_EVAL_FLAG_LAZY_FUNCTIONS` (patch 0358, `QJS_LAZY` in `vita/js/qjs.c`): the whole script is still parsed, so its syntax errors are reported when it loads, but a function's body gets bytecode only on its first call (`js_lazy_compile`), with the closure variables it was created with. While one is compiled, the functions inside it are skipped to their end, not parsed: the first parse keeps where each body inside a lazy function ends and the names it uses from outside, in its script's source blob (`JSLazyMemo`, patch 0363), so a skip seeks to the end instead of tokenizing the body again at every level of nesting; the tokenizer (`js_lazy_skip_body`) is the fallback for a script read from the cache. Not the prelude, which is kept without its source. Cache entries are serialised when the page goes quiet or closes, so they hold the functions the page called compiled. The load event line in the log says how many functions were compiled on first call and how long that took. To check a compiler change, `scripts/compile-corpus.sh` compares eager bytecode; lazy mode must report the same errors on the corpus. `Function.prototype.apply`, `Reflect.apply` and `Reflect.construct` build an argument list of up to 16 values on the C stack instead of allocating it (patch 0408): obfuscated scripts such as Cloudflare's challenge call their opcode handlers through `apply` once per instruction. A string that is not an atom keeps the atom it was found as when used as a property key (`hash_next`, patch 0410), so a name such a script keeps in a table and reaches through a helper call (`x[ak(5)](...)`) is not hashed and compared again at every use; `tests/js/string-keys.html` checks that a key still means its text after the string is appended to or made a Symbol's description. A bitwise operator whose operands are numbers but not both small integers (`x & 255.46`, `y | .56`, which obfuscators write everywhere) converts them in line in the interpreter instead of through the generic conversion (`js_number_to_int32`, patch 0411); `tests/js/bitwise-numbers.html` holds every operator to the spec over awkward values. An integer with a float64 (a sum past 2^31, `x * 0.5`, `i < n / 2`) is added, subtracted, multiplied, divided, taken modulo and compared as two doubles at the top of the slow paths (patch 0415), where it went through ToNumeric on each at some 150 instructions more; `tests/js/mixed-numbers.html` checks every operator over awkward values against the spec. A string of one Latin-1 character is made once a runtime and shared (`char_strings`, patch 0416): `String.fromCharCode`, `charAt`, `str[i]` and a one-character slice or split each allocated a new one, an allocation and a free for every character a decoding loop handles; the runtime's own reference keeps a shared one from being appended to in place. `tests/js/char-strings.html` checks it. `str.charCodeAt(i)`, the built-in itself called as a method on a flat string (or a rope already flattened) with an integer index, is read in the interpreter without the call (patch 0429): through the call it was half the time of a loop that hashes a string a character at a time, as styled-components does for every rule (16% of bbc.com's script); anything else, a replaced or borrowed method included, takes the call; the same holds when it is returned, a tail call (`return s.charCodeAt(i)`, a helper's whole body, as in eBay's sensor, patch 0446). `tests/js/char-code-at.html` checks it. A method looked up on a string primitive (`str.slice`, `str.charCodeAt` before the call) is found on String.prototype's chain in the interpreter, as an object's is, since a string's own properties are its length and indices (`OP_get_field2`, patch 0443); a getter, an exotic object on the chain or a miss takes the general lookup, which had been a seventh of that hashing loop (BBC's styled-components hash, 12% of its script). `tests/js/string-method-lookup.html` checks that a page cannot tell. The script profile in the log prints the page's own source at each hot place (`profile: here:`, `JS_GetSourceExcerpt`), keeps the 128 busiest places by the Space-Saving count (a place seen once the table is full takes the least seen one's slot and count, so a range is printed; the first 128 places had been kept for good, and reddit.com's own bundle, run after reCAPTCHA had filled the table, was counted nowhere), and totals the samples by the script of the innermost page frame (`profile: by script`), and every binding times itself from entry to return (`C_WHERE`'s cleanup, `c_where_leave`), so the report says which took longest, with any script they ran (`profile: time in bindings`), where the samples could only name the binding a stretch of C began after, and the page report says how many cycle collections ran and how long they took (`JS_GetGCStats`, patch 0409). A collection walks everything live, so the next one runs once the heap has grown by twice what the last left, at least 8 MB and at most 32 MB more (or half what is left, if that is more), and before 7/8 of the memory limit (`JS_SetGCGrowth`, patch 0414); stock QuickJS collected at half again what was left, from 256 KB, and `tests/bench/gc-churn.html?live=30000` ran 28 collections where it now runs 9. Nothing VitaSurf does for its own log may run page code or be seen by a page, since a browser's never is: the console is native (`console_say`, `console_misc` in `qjs.c`) and describes a value from its own data properties alone (`inspect_value`: a getter is named, not called, and a proxy is not asked), where it had called `String()`, getters and `toString` on whatever was logged, which is how a page tells developer tools are open, and Cloudflare's check logs such objects; and a stack for the profiler or a warning comes from `JS_GetBacktraceText` (patch 0412), which runs neither `Error.prepareStackTrace` nor a `stack` getter. `tests/js/console-quiet.html` logs trapped values and must report none run. `performance` is an instance of a `Performance` interface, `now()` is a native monotonic clock to 0.1 ms (`__vitaNow`), and User Timing (`mark`, `measure`, the entry getters) keeps entries as the specification says. An XHR's timeout counts from when the main loop is first free after `send()`, since the network here does not run beside script, and one short turn after it lets the fetcher hand over an answer already in (`timer_stage` in `struct js_xhr`); a timeout logs how long the request had.
- WebAssembly runs on WAMR's fast interpreter from `deps/wamr` (2.4.5), built by `scripts/build-wamr.sh` into `libvitawamr.a` with `vita/wasm/glue.c`, which reaches into WAMR's structures and so is built with its settings. The platform layer is `vita/wasm/platform`, picked up through `SHARED_PLATFORM_CONFIG`, so WAMR's tree has no Vita directory. Patch 0246 links imports per instance for the JS API (`vita/js/wasm.c`, `vita/js/wasm.js`).
- The Intl files (`intl_core.js` to `intl.js`) are not in the prelude every page runs: CMake embeds them as a unit of their own, which runs the first time a page touches `Intl` or a locale method (`vita/js/lazy.js` leaves lazy properties in their place; QuickJS's `JS_DefineLazyProperty` is patch 0322). Streams (`streams.js`), IndexedDB (`idb.js`, with the helpers it shares from `storage.js` in `NV.__vitaIdbNeeds`) and WebAssembly (`wasm.js`) are units the same way; what other code builds on streams (`Blob.stream`, a body's stream) is in `streams-use.js`, which runs the unit itself (`NV.__vitaRunUnit`). interfaces.js leaves a lazy global unread and shapes it when its unit has run (`NV.__vitaShapeLater`). A unit's `this` is the global, its `window` (`natives-open.js`), since a worker's global has no `window` by the time a unit runs there. A new install target in a unit needs a row in `lazy.js`. The log says when a unit ran and what touched it ("qjs: intl ... on first use of"). CMake puts a call to `__vitaPartDone` after each part of the prelude, and the log says what each cost ("qjs: prelude by part (ms)"). `tests/js/lazy-units.html` checks that a page cannot tell.
- `Intl.DateTimeFormat` is native, for every locale and calendar ICU has, as V8 has it: `vita/js/intl.js` (V8's reading of the options, SimpleDateFormat), `intl_pattern.js` (ICU's resource fallback, DateTimePatternGenerator, DateFormatSymbols), `intl_zone.js` (ICU's zoneinfo64 and zone names), `intl_calendar.js` (the other calendars, and the algorithmic numbering systems some patterns use) and `intl_range.js` (formatRange, DateIntervalFormat); `vita/js/intl.c` only reads the pack. Regenerate the pack and the page together, under the Node whose ICU the data release is, and say which ICU, CLDR and tz versions in the commit.
- `Intl.NumberFormat` and `Intl.PluralRules` are native too (`vita/js/intl_number.js`, on `intl_core.js`), for every locale ICU has, and so are `Intl.RelativeTimeFormat` and `Intl.DisplayNames` (`vita/js/intl_names.js`, on `intl_number.js`); ## Phases

Each phase must work on real hardware before the next one starts.

1. Boot: statically linked framebuffer frontend, JavaScript disabled, renders a bundled local HTML page from `app0:`.
2. Networking: SceNet and SceNetCtl initialized, curl with OpenSSL, bundled `cacert.pem`, HTTPS pages load.
3. Input: D-pad link focus, stick scrolling, touch tap and drag, IME URL entry, back and forward.
4. JavaScript: enable Duktape, then measure memory and page-load time on a fixed set of test pages.
5. Persistence: cookies, history, bookmarks, and Choices under `ux0:data/VitaSurf/`.
6. QuickJS: add QuickJS bindings (a new nsgenbind output or hand-written bindings). Done; the Duktape build was kept for comparison until QuickJS was clearly better, and has been removed.
7. Polish: bundled TrueType font via FreeType, page zoom, downloads, suspend/resume handling.
8. WebGL 1, after the load-time goal: WebGL 1 is OpenGL ES 2.0, which the Vita's GPU runs (through vitaGL or the system's GLES driver via PVR_PSP2). Pages' GLSL needs a runtime shader compiler (`libshacccg.suprx`, which users extract from their own console, or vitaGL's translator), and a WebGL canvas must reach the screen without a GPU readback every frame. WebGL 2 (OpenGL ES 3.0) is beyond this GPU.

## Vita gotchas from earlier projects

- TITLE_ID must be exactly 4 uppercase letters followed by 5 digits. A wrong format fails installation at 95-97%.
- Never use `%zu` or other size_t/64-bit format specifiers. They print garbage on the 32-bit Vita. Use `%d` or `%u` with explicit casts.
- Vita3K can pass things that fail on hardware, especially IME and startup initialization. Hardware results are the source of truth.
- ARMv7 needs stricter alignment than x86, and the native harness cannot see it. A struct member wanting 8-byte alignment (a `uint64_t`) makes any cast to that struct from a less-aligned pointer an error under the Vita build's `-Werror=cast-align`, while the same code compiles clean natively because gcc only warns for the host's alignment rules. Check a touched file with `gcc -c -Wcast-align=strict -Werror` before pushing, and prefer two `uint32_t` to one `uint64_t` in a struct reached by a cast.
- IME is fragile. Call `sceCommonDialogSetConfigParam()` before showing dialogs and keep IME buffers static or otherwise long-lived. Some IME initialization changes break app loading, so change IME code carefully and regression-test on hardware.

## Browser-specific notes

- Paths: NetSurf assumes POSIX-style paths. Put all translation to `app0:` and `ux0:` in `vita/platform/`, not scattered through the code.
- Networking: initialize SceNet before any curl call. Point curl at the bundled CA file through NetSurf's `ca_bundle` option. curl has no threaded resolver (vdpm's options), so it must never look a name up itself: `vita/platform/vita_resolve.c` looks hosts up on threads of their own, and the fetcher (patch 0392) and WebSockets hold a connection back until the address is known and hand it to curl with `CURLOPT_RESOLVE`. A lookup asks the network's DNS servers itself first (`vita/platform/vita_dns.c`, the servers SceNetCtl reports): one A query over UDP, three tries of 1.5 s across the servers, aliases followed, a truncated answer asked again over TCP, and "no such name" or "no IPv4 address" taken as answers at once, where SceNet's resolver waited out 32 s for a name with no IPv4 address. A server that refuses or fails a query (REFUSED, SERVFAIL, NOTIMP) is asked again at once, the next server first, as glibc and Chrome do. Only when no server answers, every answer was a refusal or failure, or for a name without a dot (a LAN name), is SceNet's resolver asked. The log's "dns:" lines say which lookups were slow or failed and what the server said (rcode, IPv6 only, alias, TCP), or the SceNet error. `tests/dns/dns-server.py` is a fake server for the harness (`VITASURF_DNS_SERVER`).
- Cookies follow RFC 6265 as browsers do (patch 0396): `document.cookie` neither reads nor writes HttpOnly cookies (`urldb_set_cookie_from_script`), a `Domain` without its leading dot still covers subdomains, and a `Path` that is not the request's is kept. Parsing follows Chrome (patch 0398): a comma does not end a cookie, `Max-Age` wins over `Expires`, and a Secure cookie from a page that is not https, `__Secure-` or `__Host-` without what they need, `SameSite=None` without Secure, and a name and value over 4096 bytes are refused (`tests/cookies/cookie-rules-server.py`). SameSite is enforced as Chrome has it (patch 0399): a cookie without it is Lax; each fetch knows whether it navigates a top-level window (`LLCACHE_RETRIEVE_TOP_LEVEL`) and its site for cookies comes from the document that made it, found in the window tree (`browser_window_cookie_site`), so a frame of another site than its top window is cross-site; `document.cookie` and WebSocket handshakes follow the same rules. A third party's cookie is taken (SameSite decides where it goes), only a `Domain` attribute is held to the public suffixes, so `localhost` and LAN names keep cookies, and the cookie file is version 103 (SameSite added). `tests/cookies/samesite-server.py` matches Chrome. Host-only cookies with a path are still filed under the request's port. The log's "cookie:" lines name each cookie set or refused and why, and the cookie names a 401, 403, 429 or 503 request sent; never values. `tests/cookies/cookie-server.py` is the test. `urldb_iterate_cookies` visits every path node, not only the leaves (patch 0397), so a host's domain cookies are walked too. The Start menu's "Clear this site's cookies" removes every cookie a request to the page's host would carry and logs each one's name, domain and path.
- Identity and request headers: the user agent is `Mozilla/5.0 (PlayStation Vita 3.73; Mobile) NetSurf/<version> Mobile` (patch 0401), what this is and that it is a mobile device; it replaced the Vita browser's 2012 Silk/WebKit string, which a site could see contradicted by what the engine runs, and which Cloudflare's challenges treat as an old browser (only Home Assistant pages are told Chrome 140, `ha_latest`). Requests carry what browsers send (patch 0402): `Accept-Language` from the system language (`vitasurf_languages` in `vita_platform.c`, also `navigator.languages` and so Intl's default locale), the Fetch standard's `Accept` for each destination, and Fetch Metadata (`Sec-Fetch-Site`, `-Mode`, `-Dest`, `-User`, `Upgrade-Insecure-Requests`) built in `fetch_metadata_headers` from what the fetch is for: a destination in the llcache flags (`LLCACHE_RETRIEVE_DEST_*`, derived in hlcache from the accepted content types, set for navigations, web fonts and preloads), the top-level and user flags, and the referer; a script navigation outside input carries `BW_NAVIGATE_SCRIPT`, so no `Sec-Fetch-User`; a navigation from one of the browser's own pages (history, bookmarks, the start page: `vitasurf_browser_page`) is `Sec-Fetch-Site: none`, as from Chrome's history. `Referer` follows the default referrer policy, strict-origin-when-cross-origin (`fetch_referer_header`, patch 0403), for pages and for script requests alike, and script requests send `Origin` when cross-origin or not a GET. A script request's body has the Content-Type the Fetch standard gives it (text/plain for a string, a Blob's own type, none for bytes, never curl's form default) and goes byte for byte: an ArrayBuffer, view or Blob reaches `__vitaFetch` as an ArrayBuffer, a string as its UTF-8, and `fetch_start` takes the body's length so a zero byte does not end it (patch 0404), and the headers a page may not set (Referer, Cookie, `Sec-*` and the rest) are dropped. A form submitted from script (`submit()`, `requestSubmit()`, a scripted button click) builds the HTML standard's entry list (tree order, the submitter alone of its buttons, an empty file part for an empty file input, the `formdata` event) and sends it as the standard encodes it: GET in the query, POST as urlencoded, multipart (Chrome's `----WebKitFormBoundary` form, as a FormData body in fetch also is) or text/plain, through `browser_window_navigate_post` with its own Content-Type (patch 0405); a form POST also sends `Origin`. A form the user submits goes the same way when the page has script (patch 0406): a tap on a submit button calls `js_submit` (`__vitaSubmit`), after every control's value is synced to the DOM, and Enter in a field calls `js_implicit_submit` (`__vitaImplicitSubmit`: the default button is clicked, or with none the form goes when one field alone takes Enter); a click the page cancelled submits nothing. NetSurf's own `form_submit` is left for pages without script. `tests/forms/submit-server.py` and `tests/forms/tap-server.py` match Chrome. `tests/headers/headers-server.py` gives Chrome's Fetch Metadata. A request answered 400, 401, 403, 429 or 503 logs the headers it sent (not the values of ones that may hold a secret), its body's size and Content-Type, and a `cf-mitigated` answer ("refused:" lines).
- What a page can see of the browser's own code: nothing a browser would not show. The natives the bindings make, and the functions the prelude leaves for C, are every `__vita*` name; `setup_globals` moves them off the global into a null-prototype object (`jsthread.natives`) before the prelude runs, and the prelude, like each unit run later, is one function of it (`vita/js/natives-open.js` and `natives-close.js`, first and last of the parts in CMake), so the JavaScript reaches them as `NV.__vitaX` and C as `natives_get(ctx, "__vitaX")`. Another window's or a worker's are `NV.__vitaNativesOf(global)`. A whole-tree rebuild is forced only while the page's last rebuild cost 60 ms or less, and at most 400 ms of forced layout per entry; the IntersectionObserver reads without forcing. Before the first layout getComputedStyle selects against an early context, rebuilt whenever a sheet is added or changed; the STYLEs still waiting to be converted, every one a long script adds, are parsed for it from their text and kept from one context to the next by element and text (`early_sheet` in `css.c`, patch 0433), where each context had parsed them all again: reddit.com's ten reads took 1.6 s each (`tests/dom/early-style-cache.html`, `tests/bench/early-styles.html`, 2749 ms to 253 ms natively). The STYLE's CSS content, converted after the script, takes that parse instead of parsing the same text again (`nscss_offer_parsed`, `early_sheet_take`, patch 0450): its URL is registered with the element when the content is asked for, and on conversion the early parse is taken if its text and base are the content's, it has no `@import` (which the early parse does not fetch) and the root's attributes are those it was parsed against; an early context holding it then holds the content's sheet. cnn.com's STYLEs took 3 s for its first read and as long again converted (`tests/css/early-style-taken.html`; `tests/bench/early-style-taken.html`, the time from the script to load 300 ms to 50 ms natively). The page report says how many were taken. Such a context holds only the sheets of the trees that can style the elements a read selects (`html_select_ctx_for`, `style_read_scopes` in `qjs.c`, patch 0441): the document's, each shadow tree on the way up, and the shadow root of each host on that way (its `:host` and `::slotted` rules); another tree's sheet matches nothing there. It keeps the trees it was built for while the sheets are the same, a sheet left out keeps its parse for a later read, and a built-in sheet whose fetch had not finished is parsed once, not at every build (`early_base`). reddit.com's early reads had parsed and indexed every component's STYLE, about 250, 11.6 s over fourteen reads (`tests/dom/early-style-trees.html`, `tests/bench/early-style-trees.html`, 1752 ms to 760 ms natively, the rest the new sheets' own parse). Such a read selects the element and its ancestors outside box construction, and NetSurf takes the element's and its parent's libcss data away for it, so libcss had no bloom filter of the ancestors' names and used a saturated one, which rejects nothing: every rule whose last compound matched walked its combinators, and reddit.com's reads of three elements took 1 to 4 s, cnn.com's of 24 4.7 s. libcss now makes the parent's bloom by walking its ancestors as they are now, across shadow roots (`css__build_ancestor_bloom`, patch 0437), never taking an ancestor's kept bloom, which is from when its boxes were made (a class added since must count: `tests/css/custom-property-kept-selection.html`); `tests/dom/style-read-ancestors.html` checks matching, `tests/bench/style-read-ancestors.html` the time (after load, 148 ms to 13 ms natively). The same patch makes reading a sheet linear: each rule went into its hash chain by a search from the head, and each ancestor key into its set by reading the whole set, so a sheet with thousands of rules on one key, or naming thousands of ancestor classes, read in quadratic time (the bench's 5000 rules, 230 ms to 15 ms); a chain's head keeps its tail, and a key set an index. The merged index a context selects with is built from each sheet's hash by gathering the rules, putting them in slot order by counting, and merging each chain's runs (each sheet's are in order already) into one block of entries (patch 0442): every entry had been allocated alone and every chain sorted, and the index was 345 ms each time reddit.com's early reads rebuilt it (bootstrap, bulma and the Zen Garden together, 11.3 ms to 4.4 ms natively). A sheet that says `revert` anywhere had every element keep a copy of its property table and styles at each change of origin, in case one of its declarations reverted, 40 KB written per element; they are kept now only for an element where a user or author `revert` wins, which is selected a second time with them (`revert_missed`, patch 0449), and the selection's parent bloom is left to the parent when a selection is given up (`parent_bloom`). Stack Overflow's three focus outlines had been a third of each element's selection (`tests/css/revert-lazy.html`; its selection 352M to 199M instructions natively, with the variable map sized once for an element's declarations, `css__custom_map_reserve`). The selector rewrite before parsing copies the runs between quotes and colons at once and skips a prelude without a colon, where it went a character at a time (70M to 28M). An early sheet's parse counts in the page's CSS time (patch 0438), and a slow read logs what it spent ('qjs: a computed style read took'). A token list keeps its tokens with the attribute text they came from (`_tok` in `prelude.js`), and a style declaration its text (`declText`), so `classList.contains` and a variable changed among hundreds do not split or re-read the attribute each time (`tests/bench/tokens-styles.html`). A sheet's load or error event, and a parser script waiting on sheets, may add sheets and so move `stylesheets`: `html_convert_css_callback` finds its entry again by index after them (patch 0425, `tests/dom/link-load-adds-sheets.html`, under valgrind).
- Input events: a tap sends pointerdown and mousedown on press, then pointerup, mouseup and a click on release, from where the pointer is (`fire_dom_pointer_event`, patch 0394); `html_pointer_current` carries the position to `wrap_event`. Every listener of an event NetSurf dispatches gets one object, which the prelude makes a trusted PointerEvent, MouseEvent, KeyboardEvent or FocusEvent (`__vitaNativeEvent`, kept until `js_event_cleanup`). After a click nothing cancelled, a checkbox or radio NetSurf set gets input and change, and a label, summary or popover button runs its activation in the prelude (`js_activate`, `__vitaActivate`). A click in a frame is the frame document's alone.
- Units: the build uses 96 dpi and a 12pt (16px) default font, as browsers do (`content/handlers/css/css.c`, `desktop/options.h`). NetSurf's 90 dpi made em and rem sizes 15/16 of what pages asked while px came out right, and a rem inside calc() 17px. A variable web font is set to the weight asked for (`font_freetype.c`); its default instance can be its thinnest. libcss's fixed-point add and subtract saturate as they should (patch 0431, `include/libcss/fpmath.h`): upstream did the overflow idiom in signed arithmetic, so a negative plus a positive and a negative minus a negative came out INT_MAX, and any math function that met one at layout (`calc(50vw - 720px + 1rem)` on a narrow screen, `max(1rem, calc(-50px + 1rem))`) was 2097151px; MDN laid its page out that wide and showed only its header. `tests/css/calc-math.html` checks calc, min, max, clamp, abs, sign, mod, rem and round over negative and mixed-unit values, in margins, widths, a font size and grid tracks. Container query units are units of their own (`UNIT_CQW` and the rest, patch 0440): a font size in cqw or cqi is a hundredth of the nearest container's inline size as the last layout measured it (`font_size_from_container`, through the same lookup as `@container`, so the styles are chosen again once it is measured), where every cq unit had been its viewport counterpart and Amazon's card titles at 11.8cqi were set at an eighth of the screen, three times their size; the block-size ones, and every other property, keep the viewport meaning (`tests/css/container-units.html`). Negative margins follow CSS where NetSurf's layout cut them short (patch 0445): a calc() margin counts in an element's min and max widths (`calculate_mbp_width` resolves it through the px accessor, where the plain one read it as 0px); a flex item's base size is its content plus its real margins, borders and padding, though the min/max pass counts a negative sum as nothing (`layout_flex__base_and_main_sizes`); and an inline-block of text is not lifted by a negative top margin, which only makes the line shorter (`layout_line`). stackoverflow.com's sidebar icons, 32px circles with `calc(var(--su8) * -1)` margins, were 48px ovals, and its tab counts, with -100% margins above and below, were drawn a tab's width above the tabs. A transform's translations take min(), max() and clamp() as well as calc(), and its angles and numbers (rotate, skew, scale, the `rotate` and `scale` properties) all four, where any of them dropped the whole declaration and Tailwind writes -rotate-45 as `calc(45deg * -1)` (patch 0444). A differential probe of literal against calc(), min(), max() and clamp() negatives found nothing else differing across margins, offsets, text-indent, spacing, vertical-align, floats, flex, grid, tables and logical properties. `tests/css/negative-margins.html`.

## Working rules

- NetSurf code is C99. Match NetSurf's style inside its tree and write Vita glue code in C.
- Keep upstream changes minimal. Record each one as a patch in `patches/` or guard it with `#ifdef __vita__`. Never edit submodules without recording the change.
- Log to `ux0:data/VitaSurf/log.txt`. Keep logging cheap and turn off verbose logging in release builds.
- When reporting that something works, say whether it was tested on Vita3K or real hardware.
- Commit messages: short, imperative mood.

## CI and releases

- GitHub Actions using the `vitasdk/vitasdk` Docker image. Build the VPK on every push and attach it to tagged releases.
- Release notes: no emojis or icons anywhere, including headers, tables, and bullets.
