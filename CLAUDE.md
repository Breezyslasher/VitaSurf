# CLAUDE.md

## Project

VitaSurf (working name) is a PS Vita port of the NetSurf web browser. It uses NetSurf's framebuffer frontend with a Vita-specific libnsfb surface. JavaScript starts with NetSurf's existing Duktape engine; replacing it with QuickJS is a later phase.

Goal: usable browsing of as many websites as possible, including script-heavy sites and web apps, at 960x544 with buttons and touch, with every page loaded and usable in under 20 seconds on real hardware. A site that does not work, or takes longer, is a bug to fix by making the browser faster or more correct, never by tailoring it to that site.

Non-goals: DRM/EME. Do not add, stub, or work around DRM. WebGL is not a non-goal: it is phase 8.

License: NetSurf is GPLv2, so this project is GPLv2. Every added library must be GPLv2-compatible (QuickJS is MIT, which is fine).

## Platform constraints

- CPU: 32-bit ARMv7 (Cortex-A9, NEON). Toolchain prefix `arm-vita-eabi-`. The compiler defines `__vita__`. An app runs at 333 MHz unless it asks for more: `set_clocks` in `vita_platform.c` raises the ARM clock to 444 MHz and the bus to 222 at startup, after a resume and whenever a page load finds them lower, and every page load logs them ("cpu:").
- Memory is the main constraint. The system has 512 MB total and the app gets only part of it. Set `_newlib_heap_size_user` explicitly, log free memory at startup and after each page load, and treat any unbounded cache as a bug. The newlib heap is sized at startup from the memory then free, less a reserve (`vita/platform/vita_heap.c`), so `_newlib_heap_size_user` is only its fallback. Extended memory mode (`ATTRIBUTE2=12` in the SFO) is verified on hardware and is on in every build (`VITASURF_EXTENDED_MEMORY`, default ON).
- No JIT. Both Duktape and QuickJS are interpreters, so JS performance comes from doing less work, not from engine tricks.
- Screen: 960x544. Front touch reports coordinates at 1920x1088, so divide by 2.
- `app0:` is read-only. All writable data goes under `ux0:data/VitaSurf/`.

## Build

- Requires VITASDK with `$VITASDK` set. Install dependencies with vdpm: curl, openssl, zlib, libpng, libjpeg-turbo, freetype, and SDL2 if the surface uses it. Check exact package names in vdpm before scripting them.
- vdpm's FreeType has no brotli, so it refuses every WOFF2 font, and WOFF2 is what the web serves. `scripts/build-freetype-woff2.sh` builds brotli and then FreeType against it, over the top of vdpm's copies. Without it, an icon font renders as the ligature's name: openmediavault and Audiobookshelf both show that.
- QuickJS is built from `deps/libquickjs` (quickjs-ng v0.14.0, the version vdpm ships) by `scripts/build-quickjs.sh`, not taken from vdpm. Stock quickjs-ng keeps a copy of every function's source, nested functions included, which is 35-47% of the memory compiling a large bundle takes; patch 0243 makes a script's functions share one copy. The startup log says which build is in use ("functions share their script's source").
- A page's scripts and modules are compiled with `JS_EVAL_FLAG_LAZY_FUNCTIONS` (patch 0358, `QJS_LAZY` in `vita/js/qjs.c`): the whole script is still parsed, so its syntax errors are reported when it loads, but a function's body gets bytecode only on its first call (`js_lazy_compile`), with the closure variables it was created with. While one is compiled, the functions inside it are skipped to their end, not parsed: the first parse keeps where each body inside a lazy function ends and the names it uses from outside, in its script's source blob (`JSLazyMemo`, patch 0363), so a skip seeks to the end instead of tokenizing the body again at every level of nesting; the tokenizer (`js_lazy_skip_body`) is the fallback for a script read from the cache. Not the prelude, which is kept without its source. Cache entries are serialised when the page goes quiet or closes, so they hold the functions the page called compiled. The load event line in the log says how many functions were compiled on first call and how long that took. To check a compiler change, `scripts/compile-corpus.sh` compares eager bytecode; lazy mode must report the same errors on the corpus. `Function.prototype.apply`, `Reflect.apply` and `Reflect.construct` build an argument list of up to 16 values on the C stack instead of allocating it (patch 0408): obfuscated scripts such as Cloudflare's challenge call their opcode handlers through `apply` once per instruction. A string that is not an atom keeps the atom it was found as when used as a property key (`hash_next`, patch 0410), so a name such a script keeps in a table and reaches through a helper call (`x[ak(5)](...)`) is not hashed and compared again at every use; `tests/js/string-keys.html` checks that a key still means its text after the string is appended to or made a Symbol's description. A bitwise operator whose operands are numbers but not both small integers (`x & 255.46`, `y | .56`, which obfuscators write everywhere) converts them in line in the interpreter instead of through the generic conversion (`js_number_to_int32`, patch 0411); `tests/js/bitwise-numbers.html` holds every operator to the spec over awkward values. An integer with a float64 (a sum past 2^31, `x * 0.5`, `i < n / 2`) is added, subtracted, multiplied, divided, taken modulo and compared as two doubles at the top of the slow paths (patch 0415), where it went through ToNumeric on each at some 150 instructions more; `tests/js/mixed-numbers.html` checks every operator over awkward values against the spec. A string of one Latin-1 character is made once a runtime and shared (`char_strings`, patch 0416): `String.fromCharCode`, `charAt`, `str[i]` and a one-character slice or split each allocated a new one, an allocation and a free for every character a decoding loop handles; the runtime's own reference keeps a shared one from being appended to in place. `tests/js/char-strings.html` checks it. The script profile in the log prints the page's own source at each hot place (`profile: here:`, `JS_GetSourceExcerpt`), keeps the 128 busiest places by the Space-Saving count (a place seen once the table is full takes the least seen one's slot and count, so a range is printed; the first 128 places had been kept for good, and reddit.com's own bundle, run after reCAPTCHA had filled the table, was counted nowhere), and totals the samples by the script of the innermost page frame (`profile: by script`), and the page report says how many cycle collections ran and how long they took (`JS_GetGCStats`, patch 0409). A collection walks everything live, so the next one runs once the heap has grown by twice what the last left, at least 8 MB and at most 32 MB more (or half what is left, if that is more), and before 7/8 of the memory limit (`JS_SetGCGrowth`, patch 0414); stock QuickJS collected at half again what was left, from 256 KB, and `tests/bench/gc-churn.html?live=30000` ran 28 collections where it now runs 9. Nothing VitaSurf does for its own log may run page code or be seen by a page, since a browser's never is: the console is native (`console_say`, `console_misc` in `qjs.c`) and describes a value from its own data properties alone (`inspect_value`: a getter is named, not called, and a proxy is not asked), where it had called `String()`, getters and `toString` on whatever was logged, which is how a page tells developer tools are open, and Cloudflare's check logs such objects; and a stack for the profiler or a warning comes from `JS_GetBacktraceText` (patch 0412), which runs neither `Error.prepareStackTrace` nor a `stack` getter. `tests/js/console-quiet.html` logs trapped values and must report none run. `performance` is an instance of a `Performance` interface, `now()` is a native monotonic clock to 0.1 ms (`__vitaNow`), and User Timing (`mark`, `measure`, the entry getters) keeps entries as the specification says. An XHR's timeout counts from when the main loop is first free after `send()`, since the network here does not run beside script, and one short turn after it lets the fetcher hand over an answer already in (`timer_stage` in `struct js_xhr`); a timeout logs how long the request had.
- WebAssembly runs on WAMR's fast interpreter from `deps/wamr` (2.4.5), built by `scripts/build-wamr.sh` into `libvitawamr.a` with `vita/wasm/glue.c`, which reaches into WAMR's structures and so is built with its settings. The platform layer is `vita/wasm/platform`, picked up through `SHARED_PLATFORM_CONFIG`, so WAMR's tree has no Vita directory. Patch 0246 links imports per instance for the JS API (`vita/js/wasm.c`, `vita/js/wasm.js`).
- The Intl files (`intl_core.js` to `intl.js`) are not in the prelude every page runs: CMake embeds them as a unit of their own, which runs the first time a page touches `Intl` or a locale method (`vita/js/lazy.js` leaves lazy properties in their place; QuickJS's `JS_DefineLazyProperty` is patch 0322). Streams (`streams.js`), IndexedDB (`idb.js`, with the helpers it shares from `storage.js` in `NV.__vitaIdbNeeds`) and WebAssembly (`wasm.js`) are units the same way; what other code builds on streams (`Blob.stream`, a body's stream) is in `streams-use.js`, which runs the unit itself (`NV.__vitaRunUnit`). interfaces.js leaves a lazy global unread and shapes it when its unit has run (`NV.__vitaShapeLater`). A unit's `this` is the global, its `window` (`natives-open.js`), since a worker's global has no `window` by the time a unit runs there. A new install target in a unit needs a row in `lazy.js`. The log says when a unit ran and what touched it ("qjs: intl ... on first use of"). CMake puts a call to `__vitaPartDone` after each part of the prelude, and the log says what each cost ("qjs: prelude by part (ms)"). `tests/js/lazy-units.html` checks that a page cannot tell.
- `Intl.DateTimeFormat` is native, for every locale and calendar ICU has, as V8 has it: `vita/js/intl.js` (V8's reading of the options, SimpleDateFormat), `intl_pattern.js` (ICU's resource fallback, DateTimePatternGenerator, DateFormatSymbols), `intl_zone.js` (ICU's zoneinfo64 and zone names), `intl_calendar.js` (the other calendars, and the algorithmic numbering systems some patterns use) and `intl_range.js` (formatRange, DateIntervalFormat); `vita/js/intl.c` only reads the pack. The data is in `resources/intl.pak`, from the ICU data release `gen-intl-numbers.mjs` takes as its second argument, through `scripts/gen-intl-dates.mjs` and `scripts/gen-intl-zones.mjs`, which read genrb text with `scripts/icu-res.mjs` and ICU's locale fallback tables from `scripts/icu-fallback.json` (`scripts/gen-icu-fallback.mjs` takes them from `localefallback_data.h` in ICU's source). `scripts/gen-intl-tests.mjs` writes `tests/dom/intl-datetimeformat.html`, and its `cases(true)` checks about 140,000 cases under Node. Regenerate the pack and the page together, under the Node whose ICU the data release is, and say which ICU, CLDR and tz versions in the commit.
- `Intl.NumberFormat` and `Intl.PluralRules` are native too (`vita/js/intl_number.js`, on `intl_core.js`), for every locale ICU has, and so are `Intl.RelativeTimeFormat` and `Intl.DisplayNames` (`vita/js/intl_names.js`, on `intl_number.js`); `scripts/gen-intl-names-tests.mjs` writes their page, `tests/dom/intl-names.html`, the same way. `Intl.Locale` is native as well (`vita/js/intl_tags.js`), and every Intl constructor's locales go through its canonical form (CLDR's aliases, as ICU applies them); its `getTimeZones` reads the zone index `scripts/gen-intl-zones.mjs` writes, as ICU enumerates a region's canonical zones, its `getCollations` the types of ICU's collation data, and its `getTextInfo` follows `uloc_isRightToLeft` with CLDR's script metadata; `scripts/gen-intl-tags-tests.mjs` writes `tests/dom/intl-locale.html`, and its `cases(true)` checks every alias and likely-subtags key under Node. `Intl.ListFormat` and `Intl.DurationFormat` are native (`vita/js/intl_list.js`); `scripts/gen-intl-list-tests.mjs` writes `tests/dom/intl-list.html` and must run under a Node with `Intl.DurationFormat` (24 or later) whose ICU has the same CLDR version. `Intl.Collator` and `localeCompare` are native (`vita/js/intl_collator.js`): ICU's root collation and every locale's tailoring, built offline by `scripts/gen-intl-collation.mjs` from the ICU data release whose version Node's ICU has (`icu4c-<version>-data.zip`, passed to `gen-intl-numbers.mjs` as a second argument; the runtime is a port of ICU's `handleNext`, break cache and dictionary engines (`dictbe.cpp`). It reads the same ICU data directory, which must hold the whole zip (`brkitr`, `coll`, `locales`, `unidata`). `scripts/gen-intl-segmenter-tests.mjs` writes `tests/dom/intl-segmenter.html`. ## Phases

Each phase must work on real hardware before the next one starts.

1. Boot: statically linked framebuffer frontend, JavaScript disabled, renders a bundled local HTML page from `app0:`.
2. Networking: SceNet and SceNetCtl initialized, curl with OpenSSL, bundled `cacert.pem`, HTTPS pages load.
3. Input: D-pad link focus, stick scrolling, touch tap and drag, IME URL entry, back and forward.
4. JavaScript: enable Duktape, then measure memory and page-load time on a fixed set of test pages.
5. Persistence: cookies, history, bookmarks, and Choices under `ux0:data/VitaSurf/`.
6. QuickJS: add QuickJS bindings (a new nsgenbind output or hand-written bindings). Done; the Duktape build was kept for comparison until QuickJS was clearly better, and has been removed.
7. Polish: bundled TrueType font via FreeType, page zoom, downloads, suspend/resume handling.
8. WebGL 1, after the load-time goal: WebGL 1 is OpenGL ES 2.0, which the Vita's GPU runs (through vitaGL or the system's GLES driver via PVR_PSP2). Pages' GLSL needs a runtime shader compiler (`libshacccg.suprx`, which users extract from their own console, or vitaGL's translator), and a WebGL canvas must reach the screen without a GPU readback every frame. WebGL 2 (OpenGL ES 3.0) is beyond this GPU.

## Vita gotchas from earlier projects

- TITLE_ID must be exactly 4 uppercase letters followed by 5 digits. A wrong format fails installation at 95-97%.
- Never use `%zu` or other size_t/64-bit format specifiers. They print garbage on the 32-bit Vita. Use `%d` or `%u` with explicit casts.
- Vita3K can pass things that fail on hardware, especially IME and startup initialization. Hardware results are the source of truth.
- ARMv7 needs stricter alignment than x86, and the native harness cannot see it. A struct member wanting 8-byte alignment (a `uint64_t`) makes any cast to that struct from a less-aligned pointer an error under the Vita build's `-Werror=cast-align`, while the same code compiles clean natively because gcc only warns for the host's alignment rules. Check a touched file with `gcc -c -Wcast-align=strict -Werror` before pushing, and prefer two `uint32_t` to one `uint64_t` in a struct reached by a cast.
- IME is fragile. Call `sceCommonDialogSetConfigParam()` before showing dialogs and keep IME buffers static or otherwise long-lived. Some IME initialization changes break app loading, so change IME code carefully and regression-test on hardware.

## Browser-specific notes

- Paths: NetSurf assumes POSIX-style paths. Put all translation to `app0:` and `ux0:` in `vita/platform/`, not scattered through the code.
- Networking: initialize SceNet before any curl call. Point curl at the bundled CA file through NetSurf's `ca_bundle` option. curl has no threaded resolver (vdpm's options), so it must never look a name up itself: `vita/platform/vita_resolve.c` looks hosts up on threads of their own, and the fetcher (patch 0392) and WebSockets hold a connection back until the address is known and hand it to curl with `CURLOPT_RESOLVE`. A lookup asks the network's DNS servers itself first (`vita/platform/vita_dns.c`, the servers SceNetCtl reports): one A query over UDP, three tries of 1.5 s across the servers, aliases followed, a truncated answer asked again over TCP, and "no such name" or "no IPv4 address" taken as answers at once, where SceNet's resolver waited out 32 s for a name with no IPv4 address. A server that refuses or fails a query (REFUSED, SERVFAIL, NOTIMP) is asked again at once, the next server first, as glibc and Chrome do. Only when no server answers, every answer was a refusal or failure, or for a name without a dot (a LAN name), is SceNet's resolver asked. The log's "dns:" lines say which lookups were slow or failed and what the server said (rcode, IPv6 only, alias, TCP), or the SceNet error. `tests/dns/dns-server.py` is a fake server for the harness (`VITASURF_DNS_SERVER`).
- Cookies follow RFC 6265 as browsers do (patch 0396): `document.cookie` neither reads nor writes HttpOnly cookies (`urldb_set_cookie_from_script`), a `Domain` without its leading dot still covers subdomains, and a `Path` that is not the request's is kept. Parsing follows Chrome (patch 0398): a comma does not end a cookie, `Max-Age` wins over `Expires`, and a Secure cookie from a page that is not https, `__Secure-` or `__Host-` without what they need, `SameSite=None` without Secure, and a name and value over 4096 bytes are refused (`tests/cookies/cookie-rules-server.py`). SameSite is enforced as Chrome has it (patch 0399): a cookie without it is Lax; each fetch knows whether it navigates a top-level window (`LLCACHE_RETRIEVE_TOP_LEVEL`) and its site for cookies comes from the document that made it, found in the window tree (`browser_window_cookie_site`), so a frame of another site than its top window is cross-site; `document.cookie` and WebSocket handshakes follow the same rules. A third party's cookie is taken (SameSite decides where it goes), only a `Domain` attribute is held to the public suffixes, so `localhost` and LAN names keep cookies, and the cookie file is version 103 (SameSite added). `tests/cookies/samesite-server.py` matches Chrome. Host-only cookies with a path are still filed under the request's port. The log's "cookie:" lines name each cookie set or refused and why, and the cookie names a 401, 403, 429 or 503 request sent; never values. `tests/cookies/cookie-server.py` is the test. `urldb_iterate_cookies` visits every path node, not only the leaves (patch 0397), so a host's domain cookies are walked too. The Start menu's "Clear this site's cookies" removes every cookie a request to the page's host would carry and logs each one's name, domain and path.
- Identity and request headers: the user agent is `Mozilla/5.0 (PlayStation Vita 3.73; Mobile) NetSurf/<version> Mobile` (patch 0401), what this is and that it is a mobile device; it replaced the Vita browser's 2012 Silk/WebKit string, which a site could see contradicted by what the engine runs, and which Cloudflare's challenges treat as an old browser (only Home Assistant pages are told Chrome 140, `ha_latest`). Requests carry what browsers send (patch 0402): `Accept-Language` from the system language (`vitasurf_languages` in `vita_platform.c`, also `navigator.languages` and so Intl's default locale), the Fetch standard's `Accept` for each destination, and Fetch Metadata (`Sec-Fetch-Site`, `-Mode`, `-Dest`, `-User`, `Upgrade-Insecure-Requests`) built in `fetch_metadata_headers` from what the fetch is for: a destination in the llcache flags (`LLCACHE_RETRIEVE_DEST_*`, derived in hlcache from the accepted content types, set for navigations, web fonts and preloads), the top-level and user flags, and the referer; a script navigation outside input carries `BW_NAVIGATE_SCRIPT`, so no `Sec-Fetch-User`; a navigation from one of the browser's own pages (history, bookmarks, the start page: `vitasurf_browser_page`) is `Sec-Fetch-Site: none`, as from Chrome's history. `Referer` follows the default referrer policy, strict-origin-when-cross-origin (`fetch_referer_header`, patch 0403), for pages and for script requests alike, and script requests send `Origin` when cross-origin or not a GET. A script request's body has the Content-Type the Fetch standard gives it (text/plain for a string, a Blob's own type, none for bytes, never curl's form default) and goes byte for byte: an ArrayBuffer, view or Blob reaches `__vitaFetch` as an ArrayBuffer, a string as its UTF-8, and `fetch_start` takes the body's length so a zero byte does not end it (patch 0404), and the headers a page may not set (Referer, Cookie, `Sec-*` and the rest) are dropped. A form submitted from script (`submit()`, `requestSubmit()`, a scripted button click) builds the HTML standard's entry list (tree order, the submitter alone of its buttons, an empty file part for an empty file input, the `formdata` event) and sends it as the standard encodes it: GET in the query, POST as urlencoded, multipart (Chrome's `----WebKitFormBoundary` form, as a FormData body in fetch also is) or text/plain, through `browser_window_navigate_post` with its own Content-Type (patch 0405); a form POST also sends `Origin`. A form the user submits goes the same way when the page has script (patch 0406): a tap on a submit button calls `js_submit` (`__vitaSubmit`), after every control's value is synced to the DOM, and Enter in a field calls `js_implicit_submit` (`__vitaImplicitSubmit`: the default button is clicked, or with none the form goes when one field alone takes Enter); a click the page cancelled submits nothing. NetSurf's own `form_submit` is left for pages without script. `tests/forms/submit-server.py` and `tests/forms/tap-server.py` match Chrome. `tests/headers/headers-server.py` gives Chrome's Fetch Metadata. A request answered 400, 401, 403, 429 or 503 logs the headers it sent (not the values of ones that may hold a secret), its body's size and Content-Type, and a `cf-mitigated` answer ("refused:" lines).
- What a page can see of the browser's own code: nothing a browser would not show. The natives the bindings make, and the functions the prelude leaves for C, are every `__vita*` name; `setup_globals` moves them off the global into a null-prototype object (`jsthread.natives`) before the prelude runs, and the prelude, like each unit run later, is one function of it (`vita/js/natives-open.js` and `natives-close.js`, first and last of the parts in CMake), so the JavaScript reaches them as `NV.__vitaX` and C as `natives_get(ctx, "__vitaX")`. Another window's or a worker's are `NV.__vitaNativesOf(global)`. A new native needs nothing more than its `__vita` name; a new callback for C is `NV.__vitaX = fn`, never `W.__vitaX`. `window.location` is kept in `jsthread.location_obj`, and `window[n]` exists only for the frames the page has (`syncIndexes`). Names used as internal properties on page objects (`__vitaItems`, `__vitaImpl`, `__vs*`, `__on_*`) are still visible on those objects.
- Interface objects: `vita/js/interfaces.js`, the last part of the prelude, gives every interface Chrome exposes on a window the shape WebIDL gives it, from a table generated from Chrome (name, parent, constructible or not, `length`, `Symbol.toStringTag`, constants): an illegal constructor throws Chrome's TypeError, a constructor needs `new` and its required arguments, the interface object's prototype is its parent's, `prototype.constructor` is not enumerable, and the global is writable, configurable and not enumerable. The prelude's own calls are exempt (`NV.__vitaFromPrelude`, which looks at the caller's frame); the originals of what it wraps are `NV.__vitaOrig`. interfaces.js makes the constructors' wrappers (`mk`) and `vita/js/ifaces.c` does the rest of each row (`__vitaShapeInterfaces`), which in script was a tenth of the prelude's time. The prelude's long runs of accessors (the CSS properties' names, the event handler properties, the setters that let a page assign to a read-only member) are made there too (`__vitaAccessors`, `__vitaAddSetters`): each getter and setter is a C function that passes its name to one shared script function, where each had been a closure pair defined from script. One constructor under two names (StyleSheet and CSSStyleSheet) keeps its prototype for the name the function has. A new interface is a row in TABLE (parents first); `scripts/gen-interface-tables.py` fills the row in from Chrome's `scripts/interface-dump.html` and regenerates nodes.js's tables, and `--check` says what Chrome has that the tables do not. `tests/js/interfaces.html` checks the shapes.
- Nodes: each node has its interface's prototype, under its parent's as WebIDL has it (an anchor's chain is HTMLAnchorElement, HTMLElement, Element, Node, EventTarget; a text node's Text, CharacterData, Node), and each member is on the interface Chrome has it on. The bindings give a node its prototype when they wrap it (`node_proto_for` in `qjs.c`): an element by namespace and name, a custom element's name HTMLElement, an HTML name HTML does not have HTMLUnknownElement, SVG graphics SVGGraphicsElement, any other node by type, a shadow root ShadowRoot. `vita/js/nodes.js`, before `interfaces.js`, builds the prototypes and moves each member off the one prototype the prelude defines them on (`P`, which stays HTMLElement.prototype with what is HTMLElement's and what Chrome does not have) to where `PLACE` says, then hands the table to C (`__vitaNodeProtos`, which also gives the nodes already wrapped theirs); the moving is done in C (`__vitaPlaceMembers` in `vita/js/ifaces.c`, which reads PLACE as written). So prelude code must not call an element's member on a fragment, shadow root or text node (`querySelectorAll` works on all three; `getElementsByTagName` does not). A document other than the window's keeps a prototype with what it had. `EventTarget.prototype`'s methods take a node to the bindings and anything else (`new EventTarget()`, a subclass, screen) to the prelude's listeners (`__vitaIsNode`). Element has ARIA's reflection (`ariaLabel`, `role`). `document.doctype` is the doctype node, or null. With frames on the page a node has one wrapper among all the windows, made in its node document's window (`node_home`), and the document factories make nodes in the document they are called on (`this_document`), so a frame's method applied to the top document makes a top-window node. `window[n]` follows the frames before each script the parser runs (`__vitaBeforeScript`), not a script another script inserted. Inserting a fragment puts every child in place before any DOMNodeInserted is sent (patch 0413), as the DOM's insert has it: a `<script>` among the children ran from the first one's event with the rest still pointing at the fragment, and a script that walked the document there crashed. `tests/dom/node-interfaces.html` checks it against Chrome.
- The window's objects: `vita/js/singletons.js` makes navigator, screen, screen.orientation, crypto, visualViewport, navigation and history instances of their interfaces, with every member moved to the prototype (a value becomes a getter over a store the page cannot reach, read-only unless the attribute is writable), and location a Location whose own members are enumerable, as [LegacyUnforgeable] has them, and whose address parts navigate when set. A Storage keeps its state in a WeakMap, and `localStorage` is a proxy that makes items properties (`localStorage.theme = 'dark'`, `Object.keys(localStorage)`), as WebIDL's named properties are. `performance` is `vita/js/performance.js`: every interface of the timeline (Performance, its entries and observer, PerformanceTiming, PerformanceNavigation) with its members on its prototype and its values in WeakMaps, a fresh object rather than QuickJS's own, whose `now` cannot be removed, and the document's milestones recorded from listeners added before the page's (`tests/js/console-quiet.html`). `tests/js/window-objects.html` checks the rest against Chrome. `BroadcastChannel` reaches the other channels of its name and origin in its own realm, the page's or a worker's, since there is one tab (`tests/js/broadcast-channel.html`), and `navigator.webdriver` is false, as no WebDriver is in control. `EventSource` is the HTML standard's server-sent events over `__vitaFetch`'s streamed mode (a seventh argument, `progress`, called with what has come since from the scheduler, never from inside the fetcher's callback; a request is kept while script it called runs, `busy`), with the standard's line parser, UTF-8 cut across pieces held over, Last-Event-ID and the retry time (`tests/eventsource/sse-server.py`). Trusted Types are there as Chrome has them, policies and the three types, without a Content-Security-Policy to enforce them, so sinks still take strings (`tests/js/trusted-types.html`). The Async Clipboard API writes text (a ClipboardItem's text/plain, or the text of its text/html) to the browser's clipboard (`__vitaClipboardWrite`), which the framebuffer frontend mirrors to the console's (`vita/platform/vita_clipboard.c`: SceClipboard, loaded as `SCE_SYSMODULE_CLIPBOARD`, its stub library from VitaSDK's NID database, no header; patch 0420), so a plugin such as PasteUnlock can paste it in the IME; reads are refused, since a browser asks the user first. `navigator.permissions.query` answers from what this browser has: clipboard-write granted, notifications as Notification says, what it cannot do denied (`tests/js/clipboard-permissions.html`). An interface whose prototype was made on an object its parent's prototype is not above (WebSocket and BroadcastChannel, on the EventTarget.prototype a later part replaces) is put under its parent's by `__vitaShapeInterfaces`.
- URL: `vita/js/url.c` is the URL Standard's basic URL parser in C, with the state override its setters use, the host parser (IPv4 and IPv6 addresses, opaque hosts, domains made ASCII by Punycode after UTS #46's mapping, done with QuickJS's own NFKC and lower-case tables), and application/x-www-form-urlencoded. `vita/js/url.js`, the first prelude part after the natives, makes URL (its parts in a private field, from `__vitaURLParse` and `__vitaURLSet`) and URLSearchParams (its pairs in a private field, kept in step with its URL both ways); the prelude reaches them through its own `URL` binding, not the interface object. It replaced a regular expression that was a tenth of a page's script on the Vita. `document.baseURI`, which every `href` and `src` read resolves against, is kept until the tree, an attribute or the address changes (`domGen`, `location.href`): finding the `<base>` walks the document, and nytimes.com's module preloader read every link's `href` once per module, 39,459 walks. Without a `<base>` the base is the address, or for a srcdoc or blank frame its parent's (`inherited_base`, patch 0418, since NetSurf's `base_url` keeps a removed `<base>`'s href); `tests/js/base-uri.html`. `scripts/gen-url-tests.py` writes `tests/js/url-standard.html` from the web platform tests' urltestdata.json and setters_tests.json: all 896 parsing and 278 setter cases pass (Chrome passes 805 and 248).
- Geometry: `vita/js/geometry.js` has DOMPointReadOnly, DOMPoint, DOMRectReadOnly, DOMRect, DOMRectList, DOMQuad, DOMMatrixReadOnly and DOMMatrix (WebKitCSSMatrix is DOMMatrix) as the Geometry Interfaces specification has them, values in private fields; a matrix takes a CSS transform list (px lengths, deg/rad/grad/turn angles) and rotates by Chrome's sine and cosine, exact at multiples of 90 degrees. `getBoundingClientRect` gives a DOMRect and `getClientRects` a DOMRectList. `tests/js/geometry.html` checks it against Chrome.
- Site test: the Start menu's "Site test" (`vita/input/vita_sitetest.c`) loads every URL in `ux0:data/VitaSurf/sitetest.txt` in turn (written with a default list of public sites on first use, one URL a line, `#` for a comment), gives each 60 s to finish loading and watches it 8 s more, and logs a "sitetest:" line per site after its page report, then a summary, and ends on `sitetest.html`, a table of them all. A load runs from the first time the window starts loading to the first time it stops, however often a frame starts loading in between (`vita_input_load_started`), and a site's load counts only if it began after the site was asked for (`vita_sitetest_load_started`): going to it stops the page before, whose end is not this site's. The same item stops a run. The run is kept in `sitetest.state` as it goes, so after a site crashes the browser the item reads "carry on after the crash": the site that started and never ended is counted as a crash and the run goes on from the next, with the earlier figures. It is how figures from many sites on real hardware are gathered at once.
- Navigation: a page's script navigating without the user's gesture does not cancel a load the browser started (typed, a menu, a bookmark, history: no referrer), as Chrome has it (`browser_started_load` in `qjs.c`); the page being loaded may still send itself on as it parses. The page being left kept its timers running, and old.reddit's login page took the window back from three sites in turn. `tests/navigation/browser-load-server.py`. Once the next page commits (its content asks the window for a script realm, which marks the current content `frozen_current` in `struct browser_window`, patch 0427), the page it replaces and its frames and workers are frozen while it stays on the screen and any load is under way in the window, through further navigations too (one load given up for another had let it run until the next committed: old.reddit's login page ran between three sites), until it stops being current or the window stops loading (`browser_window_scripts_frozen`, `thread_frozen` in `qjs.c`): timers, request answers and timeouts, streamed progress and WebSocket events (held in order, up to 4 MB) wait, polled every 250 ms, and go on if loading stops and the page stays. Chrome unloads the page at that point; NetSurf keeps it current until the next is ready, and ESPN's socket handlers ran 40 s into the two sites after it. The log says when a page froze, and on thawing or closing what waited. `tests/navigation/freeze-server.py`.
- Lazy images: an `<img loading=lazy>` is asked for once its box comes within 1250 px of the rows a redraw shows, as Chrome does on a fast network (`html_fetch_object_lazy`, `html_object_lazy_seen` from `html_redraw`, patch 0428); until then its object holds only the address (`lazy_url`), the page's load does not wait for it, a script changing its `src` keeps it waiting, and the speculative fetch of an inserted `<img>` (`html_process_inserted_img`) skips it. Every image had been fetched as its box was made: cnn.com asked for two hundred at once, its carousels' far below the screen, and its own images queued behind them for half a minute. `tests/images/lazy-server.py`.
- Caches: set NetSurf's cache options (such as `memory_cache_size`) low by default and make them configurable. The page report's memory lines give each page's parsed style sheets and what the fetch cache and the decoded images hold (`llcache_memory`, `image_cache_bitmap_bytes`, patch 0426). A page stopped while still loading is let go at the cache's next clean, every 20 s (`aborted` in `struct content`, patch 0423): nothing will finish its load, and it had kept its document and script heap to the end of the session.
- Main loop: NetSurf runs a single-threaded scheduler with poll-based fetching. Do not add threads unless there's a measured need. If you add any, set their stack sizes explicitly.
- Rendering: blit only damaged regions reported through libnsfb updates. Avoid uploading the full screen every frame when nothing changed.
- Suspend/resume: network connections drop on resume. Fail in-flight fetches cleanly and allow retry rather than hanging.
- Fonts: bundle a license-compatible TTF (for example DejaVu Sans). Keep NetSurf's internal bitmap font as a fallback.
- Shadow DOM: a shadow root is a libdom DocumentFragment its host owns (patch 0387), so document lookups do not see into it. Box construction, event paths (composed, retargeted) and `isConnected` cross to the host. Each author sheet in the selection context carries the tree its element is in (`css_select_ctx_append_sheet_scoped`, `nscss_tree_scope`), and its rules match only elements of that tree, so page rules stop at shadow roots and a `<link>` sheet in a shadow root styles that tree alone. A shadow tree's `<style>` is rewritten in `prelude.js` under `[data-vs-s~=key]:-vita-host`, a key for the text that every host holding it carries (each `<style>` holds its host to its key, counted, and gives it up when its text changes or it is replaced: `holdKey`), so identical sheets are parsed once whatever kind of component holds them (custom elements had been scoped by tag, and old.reddit's login page parsed one 250 KB sheet for fourteen kinds of component, 41347 rules in the index; `tests/bench/components.html` went from 96249 rules in 61 sheets to 3333 in 3). The rewriting jumps between the characters that matter with global regular expressions (`RE_HEAD`, `RE_LIST`, `skipStr`) instead of reading one at a time, four times as fast; only a compound with that marker steps out of the tree, to the first host (patch 0388). `::part()` follows `exportparts` (`part_host` in NetSurf's `css/select.c`). A host lets go of its shadow root when it is freed; while a document's tree is torn down, a shadow root leaving the pending list does not ask for the document to be destroyed again (`finalising`, patch 0424), which had torn the tree down a second time over freed elements whenever a page with a shadow root was freed (`tests/dom/shadow-teardown.html`, under valgrind).
- Style reads: while the document or a sheet has changed since the boxes were styled (`style_stale` in `vita/js/qjs.c`), getComputedStyle selects again against `html_select_ctx_now`, which parses changed `<style>` text there and then; a sheet whose element has left the document leaves the cascade (patch 0391). A geometry read (offsetWidth, getBoundingClientRect, elementFromPoint, computed width and height) runs the scheduled relayout first (`layout_flush`), but only when the outermost entry into script came from a timer, a fetch or a script element: an event NetSurf dispatches from input keeps pointers into the box tree and form controls, and reads the last layout. A whole-tree rebuild is forced only while the page's last rebuild cost 60 ms or less, and at most 400 ms of forced layout per entry; the IntersectionObserver reads without forcing. A sheet's load or error event, and a parser script waiting on sheets, may add sheets and so move `stylesheets`: `html_convert_css_callback` finds its entry again by index after them (patch 0425, `tests/dom/link-load-adds-sheets.html`, under valgrind).
- Input events: a tap sends pointerdown and mousedown on press, then pointerup, mouseup and a click on release, from where the pointer is (`fire_dom_pointer_event`, patch 0394); `html_pointer_current` carries the position to `wrap_event`. Every listener of an event NetSurf dispatches gets one object, which the prelude makes a trusted PointerEvent, MouseEvent, KeyboardEvent or FocusEvent (`__vitaNativeEvent`, kept until `js_event_cleanup`). After a click nothing cancelled, a checkbox or radio NetSurf set gets input and change, and a label, summary or popover button runs its activation in the prelude (`js_activate`, `__vitaActivate`). A click in a frame is the frame document's alone.
- Units: the build uses 96 dpi and a 12pt (16px) default font, as browsers do (`content/handlers/css/css.c`, `desktop/options.h`). NetSurf's 90 dpi made em and rem sizes 15/16 of what pages asked while px came out right, and a rem inside calc() 17px. A variable web font is set to the weight asked for (`font_freetype.c`); its default instance can be its thinnest.

## Working rules

- NetSurf code is C99. Match NetSurf's style inside its tree and write Vita glue code in C.
- Keep upstream changes minimal. Record each one as a patch in `patches/` or guard it with `#ifdef __vita__`. Never edit submodules without recording the change.
- Log to `ux0:data/VitaSurf/log.txt`. Keep logging cheap and turn off verbose logging in release builds.
- When reporting that something works, say whether it was tested on Vita3K or real hardware.
- Commit messages: short, imperative mood.

## CI and releases

- GitHub Actions using the `vitasdk/vitasdk` Docker image. Build the VPK on every push and attach it to tagged releases.
- Release notes: no emojis or icons anywhere, including headers, tables, and bullets.
